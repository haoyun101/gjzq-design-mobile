# 工作区结构 · 本地目录与权限

> **用途**:多个窗口 / agent 并行时的**本地目录约定**。
> 🏷️ **本节属项目实例层**(见 `SKILL.md` §3.0「包分两层」):里面的具体值按本项目写,**换项目整节替换**;通用的是「要有这么一节」。 本份的目录名、五目录划分、权限矩阵都是本项目的;**通用的只有「边界由目录权限保证,不靠模型自觉」这条原则**。
> ⚠️ **v7.0 起不按角色分权限**——【主线-大脑】/【主线-手】已删除(`SKILL.md` §3.1)。权限按**这个窗口够不够得到、该不该写**配,见 §二。
> **设计原则**:**边界由目录权限保证,不靠模型自觉**(`process.md` §4.8「把合规从靠自觉改为靠机制」)。
> **边界**:本文件只定**本地工作区**结构;DS skill 包**内部**结构不受影响(仍按其 `SKILL.md` 三层架构 + `SKILL.md` §2 总则3.3 全 ASCII)。

## 一、总览

工作区根路径:`{工作区根}`

```
{工作区根}/
├── skill/                      ← 【正式库】执行真值(解压后的 DS skill 目录;设计真值在 Figma,见总则1)
│   └── guojin-securities-design_vX_Y_Z/
├── drafts/                     ← 【草案区】分出去的线的产出
│   ├── common/                 ← 通用组件线
│   ├── wealth/                 ← 理财组件线
│   └── {场景}/                 ← 按需新增,用 8 业务域英文名
├── site/                       ← 【站点区】
│   ├── source/                 ← Design 原始导出
│   └── deploy/                 ← ASCII 化后可上线的部署包
├── meta/                       ← 【元文档】本工作流 skill 包 + **档案件**+**站点版本真值表**
└── 历史文件/                    ← 【归档】旧版本交付件(`process.md` §4.5)
```

**命名**
`skill/` 与 `site/` 的内容会被打包上传,内部一律 ASCII(`SKILL.md` §2 总则3.3);工作区自身的顶层目录名用 ASCII 小写,`历史文件/` 沿用 `process.md` §4.5 原名不改。
**`meta/` 里活动件的版本号用点号**(如 `_v1.4.md`),ASCII 下划线命名不适用于 `meta/`——但本工作流 skill 包是要上传的包,其顶层目录名仍走 ASCII 下划线(如 `guojin-design-workflow_v6_2/`)。

**五目录之外**
工作区根另有 `skill实际应用测试/` —— 用户私有测试区,存放发给各大模型做读取 / 挂载测试的 skill 副本与测试产物。**不属协作目录体系**:**任何窗口与 agent 一律不读、不写、不归档、不清理**,除非用户当次明确指定。归档整理(§六)时跳过该目录;保留几版由用户自行管理,不设协作侧策略。

**归档原则** → 见 §六(本处不重复,避免两处反向漂移)。

## 二、各目录职责与权限矩阵

| 目录 | 能不能写 | 注意 |
|---|---|---|
| `skill/` | **只有该线签发方能写** | 写什么由签发方裁决;**版本号由签发方签,别人不自行判断升哪位** |
| `drafts/{线名}/` | 做那条线的窗口写自己那个 | 别的线只读 |
| `site/` | 站点线写 | 打包 / 改名 / 注入都在这儿;Design 是产出源 |
| `meta/` | 够得到的窗口按需同步 | 权威副本在 `{权威副本位置}`,`meta/` 是**镜像**;**旧了不算偏差、不算待办**(`process.md` §7.2) |
| `历史文件/` | 归档时写 | 判定与处置规则见 `execution-standard.md` §八 |

**⛔ `skill/` 的唯一写入方原则**:**同一时刻只有一个窗口写 `skill/`**,就是该线的签发方。这不是角色限制,是**防两条基线并存**——实证见 `multi-window.md` §1(v6.2 / v6.3 分叉)。

**够不够得到,现场判**:哪个窗口能碰本机随载体变,按 `SKILL.md` §3.3 三分支处理——①不确定就自测或问、②够得到就自己做、③够不到就给用户或别的 agent。**不预先假设任何窗口碰不到文件。**

**系统文件不计入预期内容**:macOS 的 `.DS_Store`、`__MACOSX/` 目录及其下一切、`._` 开头的 AppleDouble 伴随文件(及同类由系统自动生成、删了会自动重建的文件)**不属于任何目录的预期内容**——收尾核对时**不报为偏差、不清理、不必请示**。只有当用户明确要求清理时才动。

> 本条最初(v6.2)只写了 `.DS_Store`,**又是一次按旧事实集写死的枚举**——`__MACOSX/` 与 `._*` 是同一类东西,只是直到 v6.6 才在实战里撞上(`multi-window.md` §8 第二条)。
> 理由:它每次都会重新出现,报一次偏差就要裁决一次,纯属噪声。

## 三、分出去的线怎么读 skill

**直接授权 `skill/` 只读**——已实测确认执行端授权可区分只读与可写,故无需副本。

- 分出去的线只授权:`skill/`(只读)+ `drafts/{自己那个}/`(读写)
- 它**够不到** `skill/` 的写权限,边界由授权保证,不靠自觉
- 够不到本机的,照旧由用户上传冷启动包(`multi-window.md` §3.2)

> 曾设计 `drafts/_skill-ref/` 只读副本方案,因授权支持只读而**取消**;该目录应清理。

## 四、草案区结构(交回格式)

每条线的目录按**批次**分文件夹,一个组件 / 一批一个:

```
drafts/common/
└── C01-button_20260902/
    ├── 交付说明.md          ← 交付包 7 项(标识/凭证/真值/嵌套/多版/裁决点/未完成)
    ├── button.html          ← 参考实现候选(须 check-page.py 0 P0)
    └── 素材/                ← 图标 SVG、截图等
```

> 🔴 **目录命名、必有哪几件、七项的内容 —— 权威全在 `multi-window.md` §5**(填写骨架见 `assets/templates/handoff-package.md`)。**本节只管「本机这棵树摆在哪」这一件事。**
> ⚠️ **够不到本机的窗口不要跳过那套约定**:落点换成权威副本所在的载体,**命名与必有项照旧**——§5 已写明两种落点。(v12.0 之前这套只写在本节,而本节挂着 🏷️ 实例层 + 只定本地,**够不到本机的会判整份不适用**,于是自己发明目录。)

**收到别的窗口交回的草案时,机械检查项** → **已并入 `multi-window.md` §5「收方怎么验」第 1 条**,本处不再重复(完整纪律见 `execution-standard.md`)。


缺项 → 标 ⚠️ 报回**交付方**,**不自行补全**(补全属裁决)。

## 五、任务卡与反馈(都不落盘)

**任务卡**(`SKILL.md` §3.3 分支③b 才有):由用户下载到 `{交接件落点}`,动手那方**直接从下载文件夹读取**,不搬进工作区。它是一次性产物,**用完即弃,不归档、不留存**。

**执行反馈**:同样是一次性过程产物。**输出为 md 文件到 `{交接件落点}`**(文件名带本轮任务编号 + 日期时分),回复只给路径;**绝不写进工作区**。写不进下载文件夹时降级为贴代码块。详见 `execution-standard.md` §五——该节形态为**安全底线**,不受单次任务卡指令覆盖。

> 故工作区**不设 `tasks/` 目录**。承 `SKILL.md` §2 总则1「事实源在文件不在对话」——事实源是 `skill/` 与 `meta/`,任务卡与反馈都不是事实源。

## 六、站点区与归档

- **`site/source/`**:Design 原始导出;**`site/deploy/`**:ASCII 化后可上线包;`SITE-CHANGELOG.md` 放 deploy 内,为站点版本唯一权威(`process.md` 总则3.5-5)。
- **`历史文件/`**:承 `process.md` §4.5 —— 各版本线**只在原位保留最新交付件**,旧版本移入此处。发布 / 打包收尾时做:**够得到本机就自己做**,够不到按 `SKILL.md` §3.3 分支③;判定与处置规则见 `execution-standard.md` §八。
