# 模板 · 开工问一次(协作参数)

> **什么时候用**:一个**新协作关系开始时用一次**——新人接手、换 agent、换载体。**不是每轮都问。**
> 答案已经记在项目侧 → **直接读,不要重复问**。规则出处:`SKILL.md` §3.0。
> ⛔ **能自测的先自测,别占用户**(§3.3 ①):够不到本机吗?能不能出图?够不到权威副本吗?——各跑一次只读动作,**把结果写进下面的问话里**,这样用户只需回答他才知道的部分。

---

## 一、给用户的问话(复制框)

```
开始之前先把这一摊的参数定一次,以后不用再问(我会记在项目侧):

1. 设计真值在哪?——哪个工具、哪个文件 / 库
2. 包和文档的「权威副本」放哪?——下一个窗口要能从那儿读到
3. 如果这一轮要碰你本机:工作区根路径是?任务卡 / 执行反馈这类交接件放哪个目录?
4. 有几条版本线、各自谁签发?
5. 有没有对外发布面(仓 / 站点)?没有的话这部分规则就不适用
   —— 有的话请给:仓名 + 分支、站点地址、本包放在仓里哪个子目录
   (这三个同时是自升级的版本源;包里现在带的是上一个项目的值,不换会把你的包覆盖掉)
6. 一个窗口做完,还是分几个窗口?有没有能直接操作你本机的 agent?
7. 你希望怎么确认和汇报?——要不要配图、一次问几件、多久汇报一次

我这边能自己试出来的已经试过了:
- 够不到你本机吗:{填实测结果}
- 能不能出图:{填实测结果}
- 够不到权威副本吗:{填实测结果}

第 3 项如果这一轮用不到,可以先不答。
```

> **只问他才知道的。** 把自测结果摆出来,是为了让用户不用回答已经有答案的问题——这也是总则4「要用户判断的东西得让他看得懂」的一部分。

## 二、答案表(抄进项目侧「协作参数」)

| 参数 | 值 | 定于 | 备注 |
|---|---|---|---|
| `{设计真值来源}` | | | 工具 + 确切文件 / 库。**换了设计工具,§4.1 / §4.7 要跟着适配** |
| `{权威副本位置}` | | | 签发后包要落到这儿(总则3.1)。**本机若另有副本 → 镜像,旧了不算待办**(§7.2) |
| `{工作区根}` | | | 够不到本机时留空 |
| `{交接件落点}` | | | 任务卡与执行反馈的读写目录;**一次性过程件,用完即弃** |
| 版本线与签发方 | | | **一条线一个签发方**(`multi-window.md` §1) |
| 对外发布面 | 有 / 无 | | **无 → §4.9 整节不适用** |
| `{发布仓}` | | | 仓名 + 分支。**发布面为无就写「无」** |
| `{站点}` | | | 对外展示站地址;没有就写「无」 |
| `{本包在仓里的子目录}` | | | 自升级按它取 `VERSION` |
| ⛔ **自升级三个默认值换了吗** | 已换 / 已 export / 已设成无 | | **包里带的是上一个项目的值**。不处理 → 一次自检就把你的包换成别人仓里那一版(`process.md` §4.6「把包分发给别人时」) |
| 协作形态 | | | 一个窗口 / 分窗口 / **只出素材不签发**;有无能碰本机的外援 agent |
| 确认与汇报习惯 | | | 两次确认是硬规则;**配不配图、一次问几件、多久汇报按人** |
| **活动件实际书名** | 档案件= · 参数件= · 校验台账= · 在途件= · 站点版本真值表= · 验证反馈件= · 改包建议件= | | 角色名见 `SKILL.md` §3.0;**没有的角色就留空,不必凑齐** |

> **每条都写「定于」(日期或来源)**。参数会变——软件迭代、换机器、换协作方式都可能改它;**没有日期就分不清哪条过期了**。
> 同类坑:包里曾把「本容器缺 rsync」当长期事实引用,而它几天后就不成立了(§4.9)。

## 三、问不到怎么办

⛔ **按保守默认走,并在交付里明着标出来——不许沉默假设。**

| 问不到的 | 保守默认 |
|---|---|
| 够不到本机吗 | **假定够不到** → 走 §3.3 分支③(推荐用户自己做,或给别的 agent 任务卡 + 提示词) |
| 有没有发布面 | **假定没有** → §4.9 整节不适用,不提推仓、打 tag、部署 |
| 协作形态 | **假定本窗口就是唯一窗口、且自己签发** → 不出任务卡、不发转接件。⛔ **但用户一说「你只出素材 / 不改包 / 不升版」,立刻切到第三形态**:不打包不升版,按 `multi-window.md` §5 七项交 `交付说明.md`(操作卡步6′) |
| 确认习惯 | **按总则4 走全套**:两次确认 + 要判断的配说明图 |

> **为什么要标出来**:保守默认会让你少做事(比如不碰本机),这通常是对的;但**用户不知道你按默认走了**,就会以为你能力不够或漏了活。
> **一句话写清「这项没问到,我按 X 默认处理」即可。**
